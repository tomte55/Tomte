# Tomte on Forever Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare Tomte, on the `forever` branch, to load on World of Warcraft: Forever on 2026-11-04 with the launch
set of modules working, without changing anything on retail.

**Architecture:** A compatibility shim in Core (`Core/Compat.lua`) hides the API names retail moved; an unlock mode
replaces Blizzard's Edit Mode where it doesn't exist; a generated second TOC loads only the foundation and the launch
set; a separate dev addon (`tools/TomteProbe`) answers the unknowns on launch day.

**Tech Stack:** WoW Lua (retail 12.1.5 and a Classic-style client), plain Lua 5.1 unit tests, Lua dev tools.

**Spec:** `docs/superpowers/specs/2026-10-25-tomte-forever-design.md`

## Global Constraints

- All work on branch `forever`. `main` gets nothing until launch day.
- Retail behavior unchanged: on retail every shim helper calls exactly the API the code calls today.
- Code that differs checks `ns.FOREVER`, never `WOW_PROJECT_ID` directly.
- The Forever TOC is generated by `tools/forevertoc.lua`, never edited by hand. Until launch it is named
  `Tomte_ForeverPending.toc` so no client loads it.
- CLAUDE.md rules apply: CRLF, edit Lua with Edit/Write only, tabs, `local addonName, ns = ...` first line, header
  comment, `ns.<Prefix>_<Name>` for cross-file functions, no `|cff`/numeric colors, no bare `pcall` around our code.
- Commits follow the batch rule: build Tasks 1-7, one combined retail test list for the user, then one commit per task
  after the user confirms. No CHANGELOG line before launch day.
- No `Data/Forever/` yet: the launch set's only content lookups (`Quests/Automation.lua:123`,
  `Nameplates/Badge.lua:276`, `Panel/Bug.lua:133`) already cope with nil. It comes with the first post-launch module
  that needs it.

## Review Focus

1. **Combat while unlocked.** Some registered widgets are secure (Fishing key, Drawers bar). `/tomte unlock` in
   combat must refuse with a message, and entering combat while unlocked must lock again. Test in Task 3.
2. **Retail with the shim failing.** If `C_AddOns.GetAddOnMetadata` errors or the tag is missing, `ns.FOREVER` must
   be `false`, never nil-indexing. Test in Task 1.
3. **A retail file added later.** A new file in `Tomte.toc` under an allowed folder must appear in the Forever TOC
   after regeneration, and one under a dropped folder must not. Test in Task 6.
4. **Unlock on retail while Blizzard's Edit Mode opens or closes.** Exiting Edit Mode must not hide boxes the user
   unlocked by command, and `/tomte lock` must not fight Edit Mode. Test in Task 3.
5. **Probe on retail.** `/tomteprobe` must run clean on retail (everything present), so it can be checked before
   launch. Covered by the Task 7 in-game check.
